# API Client and Generated Code

[[_TOC_]]

**What this page is for.** How the Angular app calls the backend: the generated client, how components use it, how errors are handled, and what to do after an API change. The generation chain itself is on [API Contracts](../Architecture/API-Contracts.md).

## The generated client

- File: `frontend/src/app/api/generated/api-client.ts` (about 30,000 lines, 70 client classes named `<Controller>Client`, for example `ClientsClient`, `TasksClient`, `DashboardClient`). Generated by NSwag from `contracts/openapi/v1.json` with `npm run api:generate`.
- **Never edit it by hand and never resolve merge conflicts in it by hand.** After a merge, rebuild the backend (to refresh the OpenAPI document) and run `npm run api:generate`.
- Method names come from the `Name = "..."` of the controller actions (`ListOnHoldReasons`, `GetDashboard`). Renaming an action renames the TypeScript method and breaks callers on purpose.
- Types: request and response records become exported classes or interfaces (`ClientResponse`, `TaskQueueRow`, ...). Use these types; do not redefine DTOs.

## How features use it

- Components and facade services inject a client class (`inject(ClientsClient)`) and call its methods, which return observables. Server data is turned into signals at the edge (`toSignal` or a small facade).
- **Initial bundle rule:** the generated module is one very large file and must not enter the initial bundle (owner limit: initial bundle under 700 kB). Eager shell code imports only **types** from it (`import type { ... }`) or loads it lazily with a dynamic `import()` (see `core/views/view-state.service.ts`, `shared/search/global-search.ts`, `core/identity-admin/http-identity-admin-api.ts`). Features are lazy routes, so they may import it normally. The guard spec `shared/layout/initial-bundle.spec.ts` checks the bundle size.
- Some areas wrap the client behind an interface so tests and the stub mode can replace it: `MeApi` (`core/auth/me-api.ts`, `HttpMeApi` or `StubMeApi`), `IdentityAdminApi`, the My Matters `mm-api.ts`, the calendar and holiday APIs. Provide the real class in `app.config.ts` or the feature routes and a fake in specs.
- `npm start` (without `:api`) runs the app against in-memory stubs and needs no backend; `npm run start:api` talks to the real API.

## HTTP behaviour (interceptors in `core/http/interceptors.ts`)

| Interceptor | What it does |
|---|---|
| `timeZoneInterceptor` | Adds `X-Time-Zone` (the viewer's zone) so the server computes overdue and "due in N days" for the viewer |
| `csrfInterceptor` | Adds `X-LptHub-Client: web` to state-changing requests (the server refuses them without it) |
| `problemDetailsInterceptor` | Converts `application/problem+json` into a typed `ApiError` (`core/http/api-error.ts`) and shows the global toast unless the request sets `SKIP_ERROR_TOAST` or is registered quiet (`QuietRequests`) |
| `connectivityInterceptor` | Feeds the connection banner when the network or API is unreachable |

Error handling in components:

- 400 with field errors: map `errors` back to form controls (`shared/forms/api-errors.ts`, `focus-invalid.ts`).
- 409 `CONCURRENCY_CONFLICT`: reload the record and offer to retry. Send the `rowVersion` you loaded on every update.
- 403 `PERMISSION_DENIED` or `ACCESS_PENDING`: the `AuthStore` refreshes the permission list; guards then route the person.
- 404 on a record: the shared record state ("We couldn't find that ...") with a generic title; never show a name from the address.
- Wording of toasts and messages comes from the shared copy tables (design guidelines section 4.3).

## After an API change

1. Backend: `dotnet build -warnaserror` (updates `contracts/openapi/v1.json`).
2. Frontend: `npm run api:generate`.
3. Fix compile errors that show where a changed type is used; run `npm test` and `npm run build`.
4. Commit the OpenAPI file and the generated client together with the backend and UI changes. CI fails on drift.
