## 4. Failures and their cause

### 4.1 SchemaTests, first attempt: 31 of 112 failed (machine, not code)

Message of all 31: `Microsoft.Data.SqlClient.SqlException: MODIFY FILE encountered operating system error 31 (A device attached to the system is not functioning.) while attempting to expand the physical file '/var/opt/mssql/data/mf_....mdf'. CREATE DATABASE failed.` The disk was full (free space fell from 2.5 GB to under 0.5 GB; the container held 2.0 GB of databases). Not a code issue. Re-run in four slices: 110 passed, **2 failed**:

- `DashboardPermissionsMigrationTests.A_fresh_database_gets_the_permission_rows_and_no_grants`: `Count should be 8 but was 10`.
- `DashboardPermissionsMigrationTests.Existing_grants_are_moved_so_nobody_loses_access`: expected 8 Dashboard permission codes, got 10 (additionally `Dashboard.ViewAbsenceReasons` and `Dashboard.ViewCalendar`).

Cause: script 60 (`60-calendar-permissions.sql`, Calendar epic #1074) adds those two codes to the group Dashboard; the test still expected the pre-Calendar list. A stale expectation in the test, the script is right. **Fixed in the test file only** (`backend/tests/MatterFlow.SchemaTests/DashboardPermissionsMigrationTests.cs`: the expected list gets the two codes, the count becomes 10). The class now passes 4 / 4, and the whole schema suite is 112 / 112.

### 4.2 `MyMattersPerformanceTests.The_number_of_statements_does_not_depend_on_the_number_of_matters`: failed, test defect (date-dependent), fixed

Message (every run): `small.Statements should be 9 but was 2` at `calendar (month, overdue)`. Failed 4 of 4 runs on the unfixed test, today (2026-11-06).

Cause: the test seeds due dates as `today + (n mod 60) - 12` days. The endpoint `my-matters/calendar?show=overdue` returns the **current month**. The person with 5 matters only holds tasks whose `n mod 60` falls in {0..4, 20..24, 40..44}, so its overdue tasks were due 8 to 12 days ago. On days 2 to 8 of any month (today is the 6th) that month holds none of them; `DayBucketsAsync` then skips its detail statements (`counts.Count == 0 ? []`) and the person with 5 matters costs 2 statements against 9 for the others. The number of statements depends on the data, not on the number of matters, so this is not a performance regression; the test breaks on a calendar date. On day 1 all three callers have none (2 = 2 = 2, passes), from day 9 on all have some. This is very probably what the earlier unconfirmed failure was: it would fail on days 2 to 8 of any month.

Fix (test only, `MyMattersPerformanceTests.cs`): the URL asks for the month of "ten days ago" (`&month={DateTime.UtcNow.AddDays(-10):yyyy-MM}`), which always holds the 8 to 12 days old overdue tasks. After the fix: 3 of 3 runs pass alone and the whole class passes (4.3). I could not run the test on another date; the proof is the arithmetic above plus the unfixed test failing 4 / 4 and the fixed one passing 4 / 4 on the same day.

### 4.3 `MyMattersPerformanceTests.The_data_reads_of_the_heavy_person_do_not_depend_on_which_person_compiled_the_plan_first`: failed once, machine load (flaky)

Message (first run, inside the 12-test class, 9 min 49 s): `data (two size fields, GB and Items), the 5-matter person compiled first: cold 669 ms, warm p95 1411 ms (ceiling 1200 ms)`. Not reproduced: 3 further runs alone (p95 336, 339, 347 ms; heavy person first 157, 168, 172 ms) and one run inside the whole class (255 ms and 147 ms). All other lines of the test: 128 to 232 ms cold, p95 at most 179 ms. The one outlier happened while other agents were running builds and tests on the same 4 cores. Classification: **flaky under machine load**, with a small real residual order effect (small person first is about twice as slow, 255 to 347 ms against 123 to 172 ms), far inside the 1,200 ms ceiling. The #938 fix (`StablePlanInterceptor`, `DISABLE_PARAMETER_SNIFFING`) holds.

The earlier failure was **real, deterministic, and caused by the date** (a test that depends on the day of the month, 4.2), not flaky and not caused by the machine. The other statement-count tests of the class (`..._of_the_my_matters_page_reads_...`, `..._of_the_pm_v2_reads_...`) pass every time (12 / 12 in the class re-run).
