# Form-rules contract: notes from the .NET implementation

Found while implementing `backend/src/Modules/MatterFlow.Configuration/Domain/Forms/Rules` against `contracts/form-rules.md` v1. All 13 notes are **resolved** (ticket #54): each decision is now normative in `contracts/form-rules.md` and locked by vectors in `contracts/form-rules.vectors.json` (152 vectors, shared by .NET and TypeScript).

1. **JSON `null` as a rule. Resolved.** JSON `null` is the same as an omitted member for every optional member (`showWhen`, `requiredWhen`, `availableWhen`, `section`, `required`, `label`, `options`, `validation` and each `validation` member). A non-object, non-null rule (string, number, boolean, array) is `SCHEMA_VIOLATION`. Vectors: `null-*`, `def-rule-string-is-schema-violation`, `def-rule-array-is-schema-violation`.
2. **Pattern semantics differ by engine. Resolved.** Patterns are restricted to a documented portable subset (form-rules.md section 3.1) and anything else is rejected at publish with the new definition code `INVALID_PATTERN`. The subset has no lookaround, named groups, backreferences, flags, `\s`, `\p` or `\u`; `\d`, `\w`, `\b` are ASCII; `.` excludes `\n \r U+2028 U+2029`; `$` matches only at the very end. .NET validates and translates `.` and `$` (`PortablePattern`) before using `RegexOptions.ECMAScript` with a 250 ms timeout; TypeScript passes the pattern to `RegExp` unchanged. Vectors: `def-pattern-*`, `pattern-*`.
3. **URL regex whitespace. Resolved.** Normative: the URL rule uses the explicit JavaScript whitespace set and end-of-input anchoring on both sides (unchanged behavior, now stated in the contract).
4. **`maxLength` count. Resolved.** UTF-16 code units; a surrogate pair counts 2. `maxLength` must be an integer 1..2147483647 (`5.0` is accepted as 5), otherwise `INVALID_VALIDATION`. Vectors: `validation-max-length-integral-float`, `def-max-length-*`.
5. **Number precision. Resolved.** NUMBER is an IEEE-754 double on both sides: `1`, `1.0`, `1e0` are equal, `-0` equals `0`, and integers or decimals beyond double precision collapse to the nearest double. Exact decimals are not promised (use text or minor units). A number that is not a finite double (`1e999`) is `INVALID_TYPE` as a value and `SCHEMA_VIOLATION` as a rule literal. Vectors: `number-*`, `def-rule-literal-beyond-double-range`.
6. **Reference ids. Resolved.** Integers 1..2^53-1 (`3`, `3.0`, `3e0` ok); larger is `INVALID_TYPE`; a larger rule literal is `LITERAL_TYPE_MISMATCH`. Vectors: `ref-*`, `def-ref-literal-above-safe-integer`.
7. **Date literal validity. Resolved.** A DATE rule literal must be a real calendar date; `2026-02-30` is `LITERAL_TYPE_MISMATCH`. Same for DATE `min`/`max` (`INVALID_VALIDATION`). Vectors: `def-rule-date-literal-impossible-day`, `def-date-max-impossible-day`.
8. **Multiple definition errors. Resolved.** Only duplicate field keys short-circuit (reported alone, compared as exact strings before any shape check). Otherwise every check runs and every distinct code is reported; a bad rule skips the rest of that rule only. Vectors: `def-duplicate-field-key-reported-alone`, `def-multiple-codes-reported-together`.
9. **Self-reference vs. other checks. Resolved.** Leaf check order is fixed: unknown field, non-input target, self reference, operator, literal, option. A heading referencing itself is `INVALID_REFERENCE_TARGET`. Vector: `def-self-reference-to-heading-is-invalid-reference-target`.
10. **`section` on a heading. Resolved.** Allowed (nested sections inherit hidden state); only self-reference or a non-heading target is `INVALID_SECTION`; heading cycles are `CIRCULAR_DEPENDENCY`. Vectors: `heading-may-belong-to-heading`, `def-section-cycle-between-headings`.
11. **Option-bearing field without options / options on non-option controls. Resolved.** SELECT, RADIO and MULTISELECT with no options (missing, `null`, `[]`) are `NO_OPTIONS`. On every other control `options` is ignored entirely (no key checks, no rules, not in the dependency graph). Vectors: `def-select-without-options`, `def-radio-empty-options-array`, `def-multiselect-null-options`, `options-on-non-option-control-are-ignored`.
12. **Field-key shape. Resolved.** New codes `INVALID_FIELD_KEY` (`^[a-z][a-z0-9_]{0,63}$`), `INVALID_OPTION_KEY` (`^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$`) and `UNKNOWN_CONTROL`. `FormSchemaJson` no longer throws on an unknown control; it yields `FormControl.Unknown`, which `FormSchema.Compile` reports. Vectors: `def-field-key-*`, `def-option-key-*`, `def-unknown-control*`.
13. **Unknown submitted keys. Resolved.** Matching is exact and case-sensitive, and a key is `UNKNOWN_FIELD` whatever its value (even `null`); error order is normalized by the consumer (the contract compares sets). Vectors: `unknown-key-is-case-sensitive`, `null-value-for-unknown-key-is-unknown-field`.
