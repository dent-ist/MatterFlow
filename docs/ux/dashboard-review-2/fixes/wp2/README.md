# WP2: page chrome, roles and fixed-height tabs (#137, #92, #93, #100; closes #114)

The Dashboard page no longer scrolls. It uses the app's fixed-header pattern (`mf-fixed-page`, `mfScrollArea`, `styles/_fixed-page.scss`): the shell is exactly one window tall (`100dvh`), the header row is always in view and only regions inside the tabs scroll. Screenshots in this folder: `*-1366.png`, `*-1920.png`, `trends-1024.png`, `*-375.png`.

## When the fixed layout is on

The window is at least **768 x 561 CSS px** (the same query as every fixed page: `FIXED_MODE_QUERY` in `shared/ui/fixed-page.ts`, `DASH_FIXED_QUERY` in `ui/dash-media.ts`). Below that (phones, a window under 561 px high, 200% zoom of a laptop) the page scrolls normally so reflow and zoom (WCAG 1.4.10) keep working. That is the only fallback and it applies to every tab; the header row stays sticky from 600 px (not below), and `scroll-padding-top` keeps a focused control clear of it.

At 1366x768, 1920x1080 and 1024x768 `document.scrollingElement.scrollHeight <= clientHeight` on every tab (`dashboard-fixed-height.spec.ts`).

## Header row (#92, #100)

- One row: H1 (20 px, still the one H1 of the page), the tab list, then stale text and Refresh at the right end. At most 56 px high from 600 px; under 600 px the H1 sits on its own line above the tabs and the row is not sticky.
- With one permitted tab (or none) the tab list is not rendered: the H1 is the tab's name ("Trends", "Swimlane", "Users", "Summary"), Refresh stays, the panel is `role="region"` named by the H1 (no orphan `tabpanel`) and `?tab=` is accepted but not written. The heading comes from `heading()` in `dashboard-page.ts`; S9 (#108) can override it there with "Unassigned work".
- Scope (P1) and Period (P3) will sit in this row when their packages land; Period is still inside the Summary and Trends bodies today.

## Width (#93)

The page container (`.dash`) is capped at 1360 px; the class `dash--wide` (Swimlane, Users with Workload and Coverage, Trends) removes the cap from 1600 px. The left edge and gutter never move between tabs. Summary and Breakdowns keep the reading cap. Trends at 1920: the flows plot is at least 1000 px wide (closes #114).

Popovers, menus and drawers are unchanged: the row menus use fixed positioning (they already live inside `mfScrollArea` grids), the drawers are overlays outside the page flow. The skip links and visually hidden helpers inside the scroll regions are contained by the positioned `.dash` container, so they never add document scroll.

## Changes of earlier decisions

- #101 rows-per-list: the 3-row cut on short windows (WP5) is removed. Every list renders its capped 5 rows; where the window is short the panel scrolls.
- #114 sticky chart (`--mf-dash-sticky-top`, `.sticky`) removed: the chart never moves, so nothing needs to stick.
- #92 "fixed-header pattern is not adopted for the Dashboard" (decision of #68) is superseded by the owner request in #137.
- The Summary tiles are two across in the tile column from 1280 px (one 220 px column before) so both groups fit a 768 px window.

## Not done here

- Scope and Period controls in the header row (WP3, WP4).
- The 480 px lane cap above 2200 px and the W5 big-screen verification (#126).
- The Users table sticky first column and sortable headers (U3, #129, WP10b); this package only provides the scroll region the sticky header relies on.
