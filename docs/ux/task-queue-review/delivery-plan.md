### Extension points (for the packages that follow)

- **Column contract (built by WP9, #200):** every `ColumnDef` (`column-prefs.ts`) declares `width`, `minWidth`, `maxWidth` (px at the default zoom), `fill?` (the Title) and `resizable?` (false for Title); a new column without them does not ship. The grid renders one `<col data-col>` per shown column in a `<colgroup>` shared by the header, filter row, group rows and skeleton; each `<col>` reads `width: var(--w-<key>)`, set as a custom property on the `table.wt` (rem); the Title `<col>` has no width and takes the rest, and `--wt-min` (sum of the fixed columns plus the 160 px Title minimum) is the table's `min-width`, so the grid scrolls sideways only below it. **Hook for the resize packages (#203 to #207):** `column-widths.ts` and the `colWidths` input of `mf-task-table`: one signal map `Record<columnKey, rem>` (sparse); a column without an entry has its default, entries are clamped to min and max, the Title never takes one (`columnWidthRem`, `widthVars`, `tableMinRem`). Convert pixels with `pxToRem` / `remToPx`: the **app's root font size is 14 px** (`html { font-size: var(--mf-fs-md) }`), not 16, so `ROOT_PX = 14` and a column declared 136 px is 136 px at the default zoom (#203 says "px at a 16 px root": store px of the default zoom and convert with these helpers). Skeleton cells keep `td[data-col]` (`task-skeleton.ts`), so widths come from the colgroup. Not fixed yet (#210): an On Hold row is 47 px (the hold reason under the Status pill), a two-line title row up to 64 px; all other Comfortable rows are 44 px (`td` height in `task-table.scss`).
- **Cells (WP8, WP14):** `mf-matter-cell` (reference over name, tooltip client and matter) and `mf-due-cell` (`layout: 'two-line' | 'inline'`, spoken sentence, `<time>`); the pure text logic stays in `core/time/time.ts` (`describeDue`). New cell content goes into a cell component, not into the `@switch (col.key)`.
- **Widths (WP17, #203, built):** `shared/work-queue/work-widths.ts`. Key `mf.work-widths.v1.<scope>.<userId>` (`anon` without a user), value `{"v":1,"w":{"due":180}}`; scope is `columnScope(page, tab)` (taskQueue, myWork.active, myWork.dueSoon, myWork.closed, myWork.createdByMe, podWork.queue, ...), no fallback between scopes, independent of density and of `mf.work-columns.v2.*`, kept while a column is hidden. **Stored numbers are integer CSS px at the default zoom (root 14 px), the API is rem** (the grid's `colWidths` unit): the module converts with `pxToRem` / `remToPx`; #203's "px at a 16 px root" is superseded by the 14 px root (see WP9). Sparse: a width equal to the column's default is not stored (pass `defaultRem` where the default differs, e.g. `pxToRem(ASSIGNEE_WITH_LINK_PX)` on Pod Work), the Title and unknown keys never are; reads clamp to the current `minWidth`/`maxWidth` and ignore non-numbers, a wrong `v` and corrupt JSON; every storage access is try/catch (blocked storage: nothing persists, nothing throws). **Functions:** `loadWidths(scope, userId): ColumnWidthMap`, `saveWidth(scope, userId, key, rem, defaultRem?)`, `resetWidth(scope, userId, key)`, `resetWidths(scope, userId)` (removes the key of the scope only), `hasWidths(scope, userId)` (for a disabled "Reset widths"), `widthsKey`, `clampPx`. **Store with signals:** `WorkWidths` (providedIn root): `widths(scope, userId)` (reading it in a computed tracks changes), `set(scope, userId, key, rem, defaultRem?)`, `reset(...)`, `resetAll(scope, userId)`, `has(scope, userId)`; a change shows at once and, with blocked storage, still holds for the visit. `QueuePageBase.colWidths` (computed from the store for the current scope and user) feeds `[colWidths]` of `mf-work-list` and `mf-task-table` on Task Queue, My Work and Pod Work, so a tab change follows by itself. The drag handle (#204), fit (#205), panel (#206) and header menu (#207) must call `WorkWidths.set` / `reset` / `resetAll` with the page's `columnScope` and user id (the page exposes them as `columnScope` and `userId`); `fitWidth(col, cells)` (#205) stays shared by the panel and the menu.
- **Narrow box (WP13, #201, built):** `shared/work-queue/narrow-columns.ts`.
